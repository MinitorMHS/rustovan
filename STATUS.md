## 2026-10-24 device-derived GPU dispatch sizing
- Replaced the global 131,072-candidate tuning ceiling with an automatic per-device ceiling. The CLI default is now `--gpu-batch 0` (automatic); a positive `--gpu-batch N` is an explicit upper cap.
- Wgpu derives its candidate ceiling from the granted storage-buffer and compute-workgroup limits. OpenCL derives it from `CL_DEVICE_MAX_MEM_ALLOC_SIZE` and `CL_DEVICE_GLOBAL_MEM_SIZE`. DX11 uses its specified dispatch-group bound. CUDA derives a limit from current free VRAM while reserving a quarter for other GPU work; its former 65,536-call rejection was removed.
- Tuning now probes geometrically increasing dispatch sizes without a global count cap, verifies parity at each size, and stops when the next projected call exceeds 1.5 seconds, a device limit is reached, or a size fails. Auto/Hybrid, direct GPU search, and the benchmark all use the same dynamic sizing path. Mnemonic probe batches use fallible reservation so a host allocation failure becomes an error instead of an allocation panic.
- This is resource-adaptive, not literally unbounded: the GPU API, usable memory, kernel integer widths, and 1.5-second cancellation target still bound a dispatch. Wgpu and OpenCL hardware ceilings and the fastest measured size remain device-specific; this Windows host has no verified RTX 3050 result.
- Windows verification: `cargo fmt --all -- --check`, `cargo check --locked --offline`, and `cargo test --locked --offline --lib --bins` passed (42 library + 12 CLI/runtime tests), including the new CLI default/manual-cap assertion and OpenCL resource-limit calculation cases. `cargo build --release --locked --offline` passed. With `--gpu-batch 128`, it reported a 128-candidate ceiling and selected 128. OpenCL on the Intel HD Graphics 4400 reported a device-derived ceiling of 3,337,420, probed through 512, and selected 256 at 481.6 candidates/s after stopping before the slower 2,059.50 ms size.
