# Production-readiness plan

This is the release plan for the current Windows-first TON vanity wallet generator. The current target is a CPU reference release with optional OpenGL/GLES PBKDF2 acceleration. Vulkan and CUDA are explicitly deferred. “Production ready” means a user can rely on the generated mnemonic, key, and address, and the distributed executable has been built, checked, and documented for the supported CPU/OpenGL matrix.

## Phase 0 — Define the supported release

- Freeze supported wallet versions, BIP39 language/passphrase behavior, derivation path, account limits, address formats, OS versions, and CPU/GPU backends.
- [x] Use OpenGL/GLES as the current GPU target; defer Vulkan and CUDA. Implementing the remaining GPU derivation stages is still an in-scope gap for the full feature matrix.
- Assign an owner and evidence record for every gate below. Keep unsupported backend claims out of release notes.

**Exit:** CPU plus OpenGL/GLES PBKDF2 support; Vulkan/CUDA remain excluded until later release validation.

## Phase 1 — Cryptographic and interoperability correctness (release blocker)

- Keep the CPU pipeline as the correctness oracle. Independently verify BIP39, SLIP-0010 Ed25519, and public-key derivation across boundary and representative account indices.
- [x] Add a separate Rust TON SDK cross-check for V4R2 and W5, covering mainnet/testnet and both bounceability settings; run it locally and wire it into Windows CI.
- Obtain independently sourced fixtures for V1R1 through V4R1 and non-default W5 wallet IDs/workchains. Record fixture provenance and verify state-init hash, workchain, friendly tag, base64url encoding, and CRC.
- [ ] Verify all supported mnemonic/passphrase normalization cases, including Unicode NFKD on CPU; clearly reject unsupported GPU inputs.
- [ ] Record independent Rust/spec provenance for the fixed SLIP-0010 and Ed25519 account vectors.
- Review TON SDK version and wallet-contract behavior against primary TON references; pin known-good dependency versions and record fixture provenance.

**Exit:** independently sourced fixtures pass on clean Windows builds, and no wallet version/network mode is supported solely by snapshots generated by the implementation under test.

## Phase 2 — Search and CLI correctness

- Exercise matcher validation, case handling, exact-match limit requirements, candidate accounting, thread bounds, account bounds, cancellation, and error propagation for CPU, auto, GPU, and hybrid paths.
- Confirm backend selection is visible and truthful; “auto” fallback and hybrid candidate counts are documented and never silently weaken correctness.
- Confirm randomness comes from the OS CSPRNG, no deterministic/reused candidate source is possible, and errors do not return partial wallet material.
- [x] Add a Rust Ctrl+C handler and shared cancellation token; CPU checks between candidates, GPU/hybrid check at batch boundaries.
- [x] Atomically reserve GPU candidate budgets before derivation; release failed-batch reservations so auto/hybrid CPU fallback can continue; validate exact friendly-address encoding/checksum and require byte-exact exact matching.
- [x] Report requested backend separately from selected GPU; clearly report CPU fallback and never auto-select deferred Vulkan/CUDA backends.
- [ ] Verify Ctrl+C stop latency, exit status, and cleanup on CPU/OpenGL paths.

**Exit:** path-by-path behavior is covered by deterministic tests and an observed CLI acceptance run; candidate counts and limits match actual work.

## Phase 3 — Secret handling and Windows hardening (release blocker)

- [x] Zeroize generated entropy, BIP39 passphrases/seeds, private-key material, and host GPU/CUDA seed buffers. GPU-owned password, parameter, seed, and staging buffers are cleared on completion and early error paths. Document residual compiler, allocator, driver, and crash-dump copies.
- [x] Create Windows secret files with a protected owner-rights DACL via CreateFileW/CREATE_NEW; a disposable CLI check confirmed a single non-inherited OWNER RIGHTS full-control ACE. Unix output remains mode 0600.
- [ ] Re-run CLI ACL/no-overwrite acceptance against the atomic sibling-temporary-file writer; the previous smoke check predates this refactor.
- [ ] Inject partial-write failures; test reparse points and process interruption; retain owner-only ACLs on every path.
- [x] Draft SECURITY.md with a vulnerability-reporting route, scope, and instructions not to submit real wallet secrets.
- [x] Run cargo-audit 0.22.2 against Cargo.lock after refreshing RustSec advisories: 0 vulnerabilities across 360 locked packages on 2026-10-10.
- [x] Inventory declared license expressions for all 360 locked packages in [docs/dependency-license-inventory.md](docs/dependency-license-inventory.md);
- [ ] Have maintainers approve license compatibility and verify private vulnerability reporting/contact configuration before release.

**Exit:** reviewed secret-flow and Windows ACL evidence; tests show output is not readable by unintended principals under the stated supported deployment model.

## Phase 4 — Backend validation

- [x] Run the PBKDF2 known-answer test and one W5 GPU-assisted search on Intel HD 4400 through OpenGL.
- [ ] For the shipped OpenGL backend, compare GPU outputs with CPU outputs over multiple batch sizes, candidate counts, supported ASCII passphrases, and boundary inputs.
- [ ] Complete OpenGL/GLES validation for the current support matrix. Vulkan and CUDA are explicitly deferred to a later release and do not block this release.
- Test recovery/failure behavior for absent adapters, driver errors, device loss, allocation pressure, and mismatched results. Any candidate returned by GPU must pass CPU re-derivation.
- [ ] Implement OpenGL GPU stages for SLIP-0010, Ed25519, TON state-init/hash/address derivation, and matching; keep CPU as the correctness reference and do not claim full GPU search before CPU/GPU parity is verified.

**Exit:** reproducible hardware/driver matrix with retained logs, CPU/GPU parity results, and no unverified shipped backend.

## Phase 5 — Build, CI, packaging, and release operations

- [x] Run formatting, locked tests, CPU-only and default builds, strict linting, release build, and the independent Rust address cross-check locally.
- [ ] Run the Windows CI workflow on the repository host and complete reproducibility checks.
- [x] Refresh RustSec advisories and run strict cargo-audit: no vulnerabilities or warnings across 360 locked dependencies on 2026-10-10.
- [x] Add a weekly and lockfile-triggered GitHub security audit workflow with pinned actions; its first hosted run remains pending.
- [ ] Review [docs/dependency-license-inventory.md](docs/dependency-license-inventory.md) against the project distribution policy.
- [x] Pin checkout and Rust toolchain CI actions to full upstream commit SHAs.
- [ ] Protect release branches/tags before production release.
- [ ] Test the packaged binary on a clean Windows 10/11 machine without the developer toolchain; verify GPU runtime guidance, output behavior, version/help text, and uninstall/update process.
- Produce signed checksums and, if adopted, signed binaries; archive build provenance, SBOM/license inventory, validation evidence, and release notes.

**Exit:** green hosted CI, clean-machine package acceptance, reviewed dependency/license report, and a documented signed artifact/provenance process.

## Current evidence and remaining gates

The current workspace has a prior passing Windows Rust test baseline, a separate Rust TON SDK cross-check for V4R2/W5, an Intel HD 4400 OpenGL PBKDF2 self-test and W5 search, and a pre-refactor Windows secret-file DACL/no-overwrite smoke check. The latest source changes pass formatting, locked default/CPU compile checks, strict Clippy, and optimized release build; tests and runtime acceptance are deferred per user request. The cross-check does not cover every legacy version; fixed derivation-vector provenance, the remaining Windows failure-path checks, hosted CI, clean-package acceptance, additional OpenGL device/driver coverage, and license approval remain open. The refreshed RustSec scan found no known advisories; repository private-reporting configuration still needs verification. Vulkan/CUDA and GPU derivation beyond PBKDF2 are deferred from this release scope. See [STATUS.md](STATUS.md), [docs/validation.md](docs/validation.md), and [docs/dependency-license-inventory.md](docs/dependency-license-inventory.md) for the detailed matrix and dependency evidence.
